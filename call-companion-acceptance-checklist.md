# MO54 Calls: чеклист приемки Android APK

Статус: `чеклист приемки`  
Дата: `2026-06-23`

## 1. Назначение

Этот документ нужен для приемки первого этапа `MO54 Calls`: Android companion-приложения для фиксации звонков Игоря.

Приемка проводится до разработки полноценного CRM-контура.

## 2. Что должен передать разработчик

- Исходный код Android-приложения.
- Инструкцию сборки.
- APK для установки вручную.
- Список поддержанных Android versions.
- Список запрошенных permissions.
- Описание выбранного способа детекции звонков.
- Описание выбранного способа записи аудио.
- Заполненный `call-recording-research-protocol.md`.
- Тестовые аудиофайлы входящего и исходящего звонка, если запись работает.
- Описание backend API или ссылку на реализованные endpoints.
- Список известных ограничений.

## 8. Аудио и автофраза

Эта часть принимается по результатам исследования на телефоне Игоря.

| Проверка | Ожидаемый результат | Статус |
|---|---|---|
| Запись входящего звонка | Аудиофайл создан или ограничение документировано |  |
| Запись исходящего звонка | Аудиофайл создан или ограничение документировано |  |
| Слышимость клиента | Подтверждена или ограничение документировано |  |
| Слышимость менеджера | Подтверждена или ограничение документировано |  |
| Автофраза | Проиграна в линию или ограничение документировано |  |
| Статус записи | Передается в backend |  |
| Аудиофайл | Загружается в backend, если создан |  |

Для v1 запись обеих сторон обязательна: три входящих и три исходящих теста подряд
должны содержать разборчивую речь клиента и менеджера. Автофраза остается
best-effort и не блокирует приемку, но ограничение фиксируется.

## 11. Блокирующие дефекты

Приемка не проходит, если:

- APK не устанавливается на телефон Игоря;
- приложение не привязывается к backend;
- входящий и исходящий звонки вообще не фиксируются;
- звонки теряются при отсутствии сети;
- форма итога не сохраняет данные;
- backend получает дубли при повторной отправке;
- приложение падает после звонка;
- разработчик не предоставил отчет по исследованию записи аудио.
- хотя бы в одном из трех последовательных входящих или исходящих тестов не
  слышна одна из сторон.

## 12. Допустимые ограничения

Допустимо, если явно зафиксировано в отчете:

- ОС не дает номер скрытого звонка;
- автофраза не может быть проиграна в линию;
- после перезагрузки требуется открыть приложение вручную, если это ограничение подтверждено и принято владельцем продукта.

Эти ограничения не должны приводить к потере metadata звонка и итога.

## 14. Итоговое решение

Возможные решения:

- `принято` — приложение можно использовать до CRM;
- `принято с ограничениями` — можно использовать, но ограничения зафиксированы;
- `не принято` — есть блокирующие дефекты;
- `нужен другой телефон` — ограничения устройства не позволяют выполнить целевой сценарий.
