# Спецификация продукта MO54 Calls v1

## Пользовательская ценность

Система помогает не потерять обращения и фиксирует результат разговора в контексте клиента. В v1 CRM управляет фактами звонка, клиентами, сделками и задачами; она не выдаёт неподтверждённые ИИ-выводы.

## Роли

- **Администратор**: пользователи, интеграции, повторная обработка, доступ к записям и журналу ошибок.
- **Менеджер**: свои звонки, контакты, сделки и задачи; работа с записью только при наличии разрешения.

## Основные сущности

| Сущность | Назначение |
|---|---|
| `users` | Менеджеры и администраторы. |
| `contacts`, `contact_phones` | Карточка клиента и нормализованные номера; один контакт имеет много звонков. |
| `companies` | Организация клиента при наличии. |
| `calls` | Метаданные, направление, длительность, источник и статус обработки. |
| `recordings` | Версии записи, состояние доступности и срок хранения. |
| `deals` | Продажи, стадия, сумма, вероятность, причина потери. |
| `tasks` | Следующий контакт, ответственный, срок и выполнение. |
| `processing_jobs` | Устойчивая очередь фоновых действий. |
| `novofon_events` | Неизменяемый журнал входящих событий провайдера. |
| `audit_log` | История ручных и системных изменений. |

## Состояния звонка

CRM различает как минимум: получен, звонок завершён, ожидается запись, ожидается транскрипт, готово, ошибка. Сбой получения записи или анализа не удаляет карточку звонка.

## Рабочие сценарии

### Входящий

1. Клиент звонит на виртуальный номер Novofon.
2. Novofon переводит вызов на мобильный номер ответственного сотрудника.
3. После завершения Novofon отправляет событие в CRM.
4. CRM сопоставляет номер с контактом или создаёт контакт, сохраняет звонок и при пропуске создаёт задачу перезвона.
5. При появлении записи CRM обновляет карточку, не раскрывая необработанную ссылку на запись.

### Исходящий

1. Менеджер открывает контакт в CRM и нажимает «Позвонить».
2. CRM просит Novofon запустить callback.
3. Сначала звонит Novofon → мобильный Redmi менеджера; после ответа соединяет с номером клиента.
4. Факт звонка приходит в CRM событием или следующей сверкой Data API.

### Задачи и сделки

Менеджер назначает следующий шаг из карточки звонка/контакта, закрывает задачу и связывает звонок со сделкой. Ручные поля CRM имеют приоритет перед автоматическими дополнениями.

## Нефункциональные требования

- Идемпотентность входящего события: повтор одного `call_session_id` не создаёт дубль.
- Webhook отвечает быстро, тяжёлая работа переносится в worker.
- Защищённая ссылка на запись доступна только авторизованному пользователю с ролью.
- Исходящий callback не должен запускаться дважды при двойном касании кнопки.
- Показатели конверсии строятся только по сохранённым фактическим исходам сделок.

## За пределами v1

- Предиктивная аналитика конверсии.
- Автоматическое изменение подтверждённых менеджером данных.
- Полноценный Android SIP-клиент как основной путь.
- ИИ-анализ без подтверждённого текста разговора и правового основания.
