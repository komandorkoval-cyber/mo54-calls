# Транскрипции и AI-саммари — безопасный rollout

## Граница данных

- Аудио, профиль Edge, SQLite-журнал, модели и конфигурация живут только в
  `%LOCALAPPDATA%\MO54CallsAgent` на домашнем ПК.
- CRM принимает только `call_session_id`, SHA-256, длительность, текст и
  сегменты через `POST /api/integrations/local-agent/transcripts`.
- URL записи, файлы аудио, cookie и пароль Novofon отклоняются контрактом API
  и не попадают в аудит.

## Что уже реализовано в этой ветке

1. `015_local_agent_transcripts.sql` добавляет происхождение транскрипта,
   хэш аудио для идемпотентности и метку спикера.
2. Endpoint ищет звонок только по стабильному Novofon `call_session_id` и
   сохраняет текст. По умолчанию это режим «только транскрипт»: задача
   `analyze` не создаётся и текст не передаётся в GigaChat.
3. После отдельного разрешения и только для утверждённого оператором текста
   включается `LOCAL_AGENT_ANALYSIS_ENABLED=true`. Тогда worker получает
   текст вместе с проверенным таймлайном сегментов и создаёт summary/insight
   и черновики действий с evidence. Для текста локального агента worker
   принимает только `LLM_PROVIDER=gigachat` с непустым credential и не может
   переключить его на OpenAI/Ollama. Он не обновляет поля звонка с выводами
   ИИ; сделки, контакты и задачи меняются только существующим ручным
   подтверждением.
4. Локальный агент обрабатывает первое окно в 7 дней и новые звонки, а аудио
   удаляет не раньше 21 дня и только после статуса `sent` — подтверждённой
   доставки текста в CRM.
5. `review-pilot CALL_SESSION_ID` работает на `127.0.0.1`: аудио не покидает
   домашний ПК. Оператор выбирает первого говорящего и ставит `Enter` только
   в тексте перед фразой следующего человека; редактор переключает роль
   следующей реплики. Плеер остаётся необязательным средством проверки, а
   временные границы не создаются и не оцениваются. Исходный автотранскрипт сохраняется только как локальный эталон;
   в CRM уходит утверждённая review-версия. Её целостность подтверждается
   отдельным ключом Windows Credential Manager, а не простым хэшем файла.

## Выпуск в production (отдельно от этой локальной работы)

### Серверная граница

Выпуск выполняется только из `/opt/asterisk-crm` и только для Compose-проекта
`asterisk-crm`. Перед изменением фиксируется read-only состояние **только**
Calls-сервисов:

```sh
cd /opt/asterisk-crm
docker compose -p asterisk-crm ps api worker
docker compose -p asterisk-crm logs --tail 100 api worker
```

Для точечного применения миграции используется одноразовый migration-контейнер
этого же проекта, а не общий `compose up` и не глобальная Docker-команда:

```sh
docker compose -p asterisk-crm run --rm --no-deps migrate /bin/sh -ec \
  'PGPASSWORD="$POSTGRES_PASSWORD" psql -v ON_ERROR_STOP=1 -h postgres \
   -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /migrations/015_local_agent_transcripts.sql'
docker compose -p asterisk-crm up -d --build --no-deps api worker
docker compose -p asterisk-crm exec -T api python -c \
  "import urllib.request; urllib.request.urlopen('http://localhost:8080/health', timeout=5).read()"
docker compose -p asterisk-crm logs --tail 100 api worker
```

Запрещены `docker system prune`, общий `compose down`, `docker restart`,
изменения nginx/портов/DNS/firewall и любые команды вне этого каталога.
`/opt/mo54`, `mo54.service` и контейнеры Планировщика намеренно даже не
запрашиваются: отсутствие доступа к ним обеспечивается списком строго
ограниченных команд выше, а не чтением запрещённых ресурсов.

1. Сначала выполнить тесты и применить release из ветки
   `phase/transcription-ai`; этот документ не даёт команд для прямого изменения
   VPS.
2. В защищённом `asterisk-crm/.api.secrets.env` создать новый случайный
   `LOCAL_AGENT_TOKEN` длиной не менее 32 символов. Он не должен совпадать с
   Novofon, webhook или browser-session секретами. Тот же токен вводится в
   Windows Credential Manager командой `set-crm-token`; в терминал и Git он
   не попадает.
3. Применить миграцию `015` и выпустить только `api` и `worker` проекта
   `asterisk-crm`. Перед включением анализа убедиться, что в `/opt/asterisk-crm/.env`
   заданы `LLM_PROVIDER=gigachat` и непустой `GIGACHAT_AUTH_KEY`, не выводя
   его значение. Для этого одобренного пилота установить в том же `.env`
   `LOCAL_AGENT_ANALYSIS_ENABLED=true`; при отсутствии credential остановить
   выпуск до доставки, а не создавать заведомо неуспешную задачу анализа.
4. На домашнем ПК вручную войти в отдельный Edge-профиль, выполнить
   `inspect-layout`, затем `inventory` (только последние 7 дней). Выбрать
   один свежий `call_session_id` и последовательно выполнить
   `download-pilot`, `transcribe-pilot` и `review-pilot`. До явного
   утверждения review-версии `deliver-pilot` блокируется. После доставки
   worker создаёт только саммари и reviewable-черновики с точными цитатами.
5. Повторить тот же ручной процесс максимум для четырёх дополнительных
   выбранных звонков. Задача Windows `MO54CallsAgent` остаётся выключенной
   до успешной приёмки всех пяти звонков.

## Приёмка перед расписанием

Для 1–5 выбранных звонков подтвердить, что повторный `deliver-pilot` не
создаёт вторую версию для того же SHA-256, неверный/отозванный токен не создаёт
данных, а запись привязана только к существующему `call_session_id`. Для
каждого ИИ-черновика evidence должен ссылаться на существующую вручную
утверждённую реплику той же версии транскрипта — с точными ordinal, началом,
концом и дословной цитатой; применение черновика остаётся ручным.
Перед включением расписания аудио, URL, cookie и пароль должны отсутствовать в
VPS, а все неотправленные записи должны остаться локально. Аудио со статусом
`sent` может удаляться не ранее 21 дня; всё остальное сохраняется для
безопасного повтора.

`deliver-pilot` дополнительно сверяет длительность сохранённого аудио с
длительностью из инвентаризации. Допускается обычная разница времени
соединения — максимум 15 секунд или 15%; более крупное расхождение блокирует
доставку до ручной проверки.

## Отзыв и восстановление

- Для немедленного отзыва замените или удалите `LOCAL_AGENT_TOKEN` в
  `.api.secrets.env` и пересоздайте API-контейнер с обновлённым окружением. Повторная доставка получит `401` или
  `503`, а локальный агент сохранит текст и попробует позже после новой
  настройки токена.
- Не удаляйте незавершённое аудио ради места. В low-space режиме агент удаляет
  только самые старые записи со статусом `sent`; всё остальное остаётся для
  безопасного повтора.
