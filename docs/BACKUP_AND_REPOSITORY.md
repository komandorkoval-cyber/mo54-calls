# Контрольные точки, резервные копии и GitHub

## Что является резервной копией сейчас

Текущая контрольная точка содержит исходный код, конфигурационные шаблоны и документацию. Она **не содержит**:

- рабочие `.env` и ключи API;
- записи разговоров, очереди и PostgreSQL-дампы;
- Android APK, pcap-дампы, диагностические утилиты и build-артефакты.

Это намеренно: база до пилота состоит из тестовых данных, а архивирование ключей или разговоров рядом с исходниками небезопасно.

После инициализации Git создаются два независимых локальных артефакта в `backups/`:

- `mo54-calls-2026-08-11-source.bundle` — переносимая история Git;
- `mo54-calls-2026-08-11-source.zip` — снимок дерева исходников текущего коммита.

Их хеши записываются в `backups/CHECKSUMS-2026-08-11.txt`. Папка `backups/` исключена из Git, поэтому при публикации нужно хранить эти файлы отдельно: на зашифрованном внешнем носителе или в защищённом облаке.

## Когда появятся реальные данные

До начала работы с реальными клиентами нужно настроить отдельную серверную резервную копию PostgreSQL. Пример направления (адаптировать к фактическим переменным на VPS):

```bash
cd /opt/asterisk-crm
umask 077
docker compose -p asterisk-crm exec -T db \
  pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" \
  > "backups/crm-$(date +%F).sql"
```

Файл дампа не должен попадать в Git или на общий диск. Обязательна периодическая тестовая проверка восстановления на отдельной базе. Записи разговоров остаются у Novofon согласно выбранному сроку хранения и правовому основанию.

## Репозиторий GitHub

Репозиторий должен быть **приватным**. Публичный репозиторий не подходит, даже если `.gitignore` настроен: в истории могут появиться номера, конфигурации или ошибочно добавленные секреты.

На GitHub создайте пустой private repository без README, `.gitignore` и license. Затем с рабочего компьютера добавить его как remote:

```powershell
git remote add origin <URL-приватного-репозитория>
git push -u origin main --tags
```

Если GitHub попросит аутентификацию, используйте вход браузером или personal access token с доступом только к этому приватному репозиторию. Никогда не отправляйте токен в чат.

## Перед каждой отправкой в Git

```powershell
git status
git diff --cached --check
git log --oneline -5
```

Проверить, что в список файлов не попали `.env`, `private/`, `recordings/`, `queue/`, `backups/`, `*.pcap`, дампы или APK. При сомнении не коммитить файл до ручной проверки.
