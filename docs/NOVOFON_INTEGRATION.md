# Интеграция Novofon

Этот документ описывает целевой мобильный контур MO54 Calls. Он не содержит API-ключей, номеров сотрудников, паролей или URL с секретом.

## Назначение

```text
Клиент → виртуальный номер Novofon → мобильный Redmi менеджера
CRM на Redmi → Call API Novofon → обратный вызов менеджеру → клиент
Novofon → HTTP-уведомления → MO54 Calls
```

SIP/Asterisk и WireGuard не являются боевым путём. Они сохранены только для диагностики и не должны участвовать в настройке входящих звонков.

## Что уже настроено

- Городской виртуальный номер активен и направлен на сотрудника «Администратор».
- Мобильный номер Redmi стоит первым в порядке дозвона; SIP-номер отключён для боевого сценария.
- Включена запись всех разговоров.
- В личном кабинете включены Data API и Call API.
- API-ключ создан и его использование разрешено.
- Публичный IP VPS добавлен в белый список доступа к API.
- Созданы два HTTP-уведомления: завершение звонка и управление записью разговора.

## Секреты и серверное окружение

Хранить значения только в серверном файле окружения, доступном контейнерам CRM. Никогда не вставлять их в браузерный JavaScript, документацию, тикеты поддержки или Git.

```dotenv
NOVOFON_API_KEY=<секретный API-ключ Novofon>
NOVOFON_WEBHOOK_SECRET=<случайная строка не менее 32 символов>
NOVOFON_WEBHOOK_ALLOWED_IPS=<IP-адреса отправителей Novofon через запятую>
NOVOFON_ACCOUNT_TIMEZONE=Europe/Novosibirsk
```

Если ключ был показан в скриншоте, чате или вставлен в незащищённый документ, его надо немедленно перевыпустить в Novofon и заменить на сервере.

## HTTP-уведомления

Для каждого уведомления должны быть включены следующие правила.

| Событие Novofon | Метод | Назначение |
| --- | --- | --- |
| Завершение звонка | POST | Создание или обновление карточки звонка, длительности, направления и задачи на перезвон |
| Управление записью разговора | POST | Обновление состояния записи и защищённой ссылки на неё |

Адрес обоих уведомлений имеет вид:

```text
https://calls.мягкиеокна54.рф/api/integrations/novofon/<секрет-пути>/events
```

Точный `<секрет-пути>` берётся из серверного окружения. В теле каждого POST добавляется ключ интеграции, который CRM проверяет до сохранения события. Условие уведомления: виртуальный номер **точно соответствует** рабочему городскому номеру в международном формате без `+`.

CRM сразу отвечает `2xx`, неизменно сохраняет входящее событие и обрабатывает его отдельно. Повторная доставка и иной порядок событий не должны создавать дубликат: ключом служит `call_session_id` Novofon.

## Настройка сотрудника и номера

В личном кабинете Novofon:

1. У сотрудника оставьте мобильный Redmi включённым первым в порядке дозвона, рекомендуемое время — 30 секунд.
2. Отключите SIP-номер в боевом порядке дозвона, чтобы не было зависших вызовов в неработающий контур.
3. Установите «Запись разговоров: для всех звонков».
4. В управлении городским номером выберите «Переадресация на: Сотрудника» и выберите этого сотрудника.
5. Не используйте системную звонилку для исходящих продаж: исходящий должен запускаться кнопкой «Позвонить» из карточки контакта CRM.

## Проверка после изменения

Выполнять тесты только на тестовых телефонах, до уведомления реальных клиентов о записи.

1. Внешний телефон звонит на городской номер.
2. Redmi получает обычный мобильный вызов, разговор устанавливается в обе стороны.
3. После завершения в отчёте Novofon есть запись о звонке и, когда доступно, кнопка воспроизведения записи.
4. В CRM один раз появляется звонок с правильным направлением, номером и длительностью.
5. Для пропущенного звонка в CRM появляется одна задача «Перезвонить по пропущенному звонку».
6. В карточке обработанного звонка ссылка «Открыть запись в Novofon» доступна только уполномоченному пользователю.
7. Из контакта CRM запустите исходящий тест: сначала звонит Redmi, затем после ответа соединяется тестовый клиент. Это отдельная обязательная проверка Call API.

## Если что-то не работает

| Симптом | Первое действие |
| --- | --- |
| Redmi звонит, но у клиента идут гудки | В отчёте Novofon открыть детализацию; проверить, что мобильный номер активен и первым в порядке дозвона. |
| Звонок есть в Novofon, но нет в CRM | Открыть журнал HTTP-уведомлений Novofon, сверить ответ endpoint и события `call_session_id`; затем проверить worker CRM. |
| В CRM нет ссылки на запись | Убедиться, что запись появилась у Novofon и что отправлено уведомление «Управление записью разговора». |
| Исходящий из CRM не начинается | Проверить Call API, белый список IP VPS, ключ Novofon и логи API CRM. Не обходить проблему звонком из системной звонилки. |
| Время кажется московским | CRM отображает `Asia/Novosibirsk`; проверить `NOVOFON_ACCOUNT_TIMEZONE=Europe/Novosibirsk` и перезапустить worker после изменения. |
