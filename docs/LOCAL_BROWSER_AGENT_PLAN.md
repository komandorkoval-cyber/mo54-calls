# Локальный агент записей Novofon — план следующей сессии

## Цель и границы

Агент запускается только на домашнем Windows-ПК, в отдельном профиле браузера с уже выполненным входом в Novofon. Он открывает список звонков, находит запись, нажимает штатную кнопку сохранения в браузере и обрабатывает файл локально.

- Не скачивать записи на VPS и не менять `/opt/mo54`, `mo54.service` или контейнеры MO54.
- Не пытаться получать аудио напрямую по временной ссылке Novofon: проверено, что она работает в авторизованной браузерной сессии, а не как серверная ссылка.
- Не хранить пароль Novofon в коде, `.env`, Git или журнале агента. Вход выполняется один раз вручную в выделенном профиле браузера.
- До появления подтверждённого транскрипта не отправлять в CRM ИИ-выводы и не отмечать разговор обработанным.

## Режим работы

1. Первый запуск просматривает только последние **7 дней**.
2. Далее агент регулярно просматривает новые/ещё не обработанные звонки; повторный запуск не должен повторно скачивать тот же разговор.
3. Локальная SQLite-база хранит идентификатор звонка Novofon, время, длительность, статус, хэш файла, путь, статусы скачивания и транскрибации. Она является источником истины, а не имя файла.
4. Аудио сохраняется только в выделенную локальную папку агента. После успешной транскрибации хранится **21 день**, затем удаляется. Транскрипт, техническая карточка и хэш остаются.
5. Если свободного места становится меньше согласованного порога (по умолчанию: меньше 10 GiB **или** 15% диска), агент показывает локальное уведомление и автоматически сокращает срок хранения, удаляя только самые старые **успешно транскрибированные** файлы. Необработанные, ошибочные и ожидающие расшифровки файлы удалять нельзя.
6. Если после такой очистки места всё ещё недостаточно, агент останавливает новые загрузки и оставляет заметное уведомление; удалять непройденные звонки ради продолжения работы запрещено.

## Сон и блокировка Windows

- Задача Планировщика Windows должна иметь флажок «Разбудить компьютер для выполнения задачи».
- Пока агент реально скачивает или расшифровывает файл, он запрашивает у Windows запрет сна; постоянно удерживать ПК бодрствующим вне работы не нужно.
- Использовать режим «Выполнять только при входе пользователя в систему»: браузер остаётся в пользовательской сессии, а пароль не передаётся Планировщику.
- При заблокированном экране агент пытается работать, но не обходит блокировку Windows и не гарантирует управление UI браузера. При невозможности взаимодействия он фиксирует безопасную причину и повторяет работу после разблокировки/следующего цикла.

## Последовательность реализации

1. Создать отдельный каталог данных в `%LOCALAPPDATA%\\MO54CallsAgent` и отдельный профиль Chromium/Edge. Не использовать действующий личный профиль браузера.
2. Реализовать read-only инвентаризацию списка звонков Novofon и локальный журнал идемпотентности.
3. Реализовать штатное действие «Сохранить» в браузере и проверку завершения загрузки: размер, расширение, хэш и сопоставление с записью журнала.
4. Выбрать и отдельно согласовать движок ASR. Не загружать модели Whisper, не ставить Docker и не отправлять аудио внешнему сервису до оценки места на диске, ресурсов ПК, стоимости и правового режима.
5. После ASR сохранять текст локально; передачу в MO54 Calls делать отдельным этапом и только текстом через аутентифицированный API. Ни аудио, ни cookie браузера на VPS не передавать.
6. Добавить Windows-уведомления, журнал без персональных данных и безопасный отчёт о месте на диске.

## Приёмочные проверки

- Один новый тестовый звонок появляется в журнале, скачивается один раз и после перезапуска не дублируется.
- Исторический запуск не выходит за окно 7 дней.
- Файл из авторизованного браузера воспроизводится локально; его хэш и длительность записаны в SQLite.
- При недостатке места старый успешно обработанный файл удаляется первым, а необработанный остаётся.
- При блокировке/сне нет бесконечного цикла и потери записи: попытка переносится на следующий запуск.
- Транскрипт и дальнейший ИИ-анализ появляются только после явного успешного статуса ASR.

## Нерешённые решения для новой сессии

- Точный ASR-движок и допустимая стоимость/место под модель.
- Канал критических уведомлений помимо локального Windows-уведомления (например, Telegram или email).
- Частота сканирования и дневной лимит скачиваний.
- Доступ агента к CRM для передачи **только транскрипта**.
