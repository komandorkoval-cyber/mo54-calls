# MO54 Calls — статус на 11 августа 2026

Статус документа: **актуальный контрольный срез**.

## Цель v1

Дать продажнику устойчивый цикл: звонок → карточка клиента → следующий шаг → задача. CRM не должна терять звонок, даже если запись или внешняя интеграция появятся позже.

## Текущая архитектура

```text
Входящий: клиент → виртуальный номер Novofon → Redmi по мобильной сети
Исходящий: CRM в браузере Redmi → callback Novofon → Redmi → клиент
События:  Novofon → защищённый webhook CRM → звонок / контакт / задача
```

CRM опубликована отдельно на `https://calls.мягкиеокна54.рф`. Основной MO54 и его домен не должны изменяться. API CRM находится за nginx и не должен быть открыт напрямую наружу.

## Подтверждено на практике

- Виртуальный номер Novofon активен.
- Номер направлен на сотрудника «Администратор».
- Для сотрудника первым активным номером указан мобильный Redmi; SIP-номер отключён как путь приёма.
- Входящие тестовые звонки доходят на Redmi по обычной мобильной связи.
- В отчётах Novofon есть принятый входящий тестовый звонок; в его детализации доступны элементы записи.
- CRM принимает события Novofon: в списке CRM появились звонки источника `Novofon`, а для пропущенных звонков созданы задачи перезвона.
- HTTPS-адрес CRM доступен.
- Data API и Call API включены в кабинете Novofon, ключ API сохранён только в серверном окружении, а доступ к API ограничен IP VPS.

## Реализовано в коде

- Предметная CRM-модель: пользователи, контакты, звонки, записи, расшифровки, инсайты, сделки, задачи, задания обработки и журнал аудита.
- Идемпотентный приём внешних событий Novofon по `call_session_id`, сохранение исходного события и асинхронная обработка.
- Защищённый webhook с секретом в пути, проверкой IP источника и быстрым ответом `2xx`.
- Автосоздание задачи для пропущенного звонка.
- Сверка данных с Data API за последние 24 часа для восстановления пропущенных webhook-событий.
- Инициирование callback-звонка из CRM с защитой от двойного нажатия.
- Ссылки на запись не включаются в обычные API-ответы; доступ проверяется по роли.
- Cookie-сессия HttpOnly, ограничения попыток входа, проверка Origin для изменяющих запросов.
- Отображение времени CRM в зоне `Asia/Novosibirsk`; входящие метки Novofon интерпретируются как время кабинета провайдера (`Europe/Moscow`).

## Намеренно выключено или отложено

- Автоматический ASR, GigaChat-саммари и ИИ-рекомендации для Novofon. Пока нет подтверждённого легального источника транскрипта, CRM не должна создавать ИИ-выводы.
- Android SIP + WireGuard как боевой путь. Тесты показали, что Redmi прекращает keepalive в фоне; это диагностическая, не боевая ветка.
- Asterisk не удалён, но не критичен для текущего запуска.

## Обязательно проверить до реальных клиентов

1. Сделать новый принятый тестовый входящий звонок после создания обоих HTTP-уведомлений и убедиться, что в CRM обновились длительность/статус записи и доступна защищённая ссылка на запись.
2. Проверить исходящий callback: кнопка «Позвонить» в CRM → звонок на Redmi → после ответа соединение с тестовым клиентом → одна карточка звонка в CRM.
3. Проверить Data API-сверку: временно отключить один webhook, выполнить тест, вернуть webhook и подтвердить восстановление звонка без дубликата.
4. Провести 10 входящих и 10 исходящих тестов подряд.
5. Проверить смену стартового пароля CRM, роли доступа и срок хранения записи у Novofon.
6. До боевого использования закрепить юридическое уведомление о записи разговоров и правила доступа сотрудников.

## Критические ограничения

- Не менять `/opt/mo54`, `mo54.service` и контейнеры MO54.
- Не хранить в Git ключи Novofon, пароли, `.env`, записи разговоров, pcap, дампы БД или диагностические APK.
- Не считать тестовые/нулевые звонки показателями конверсии.
