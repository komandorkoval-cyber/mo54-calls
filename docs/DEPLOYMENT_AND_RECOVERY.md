# Развёртывание и восстановление

## Неприкосновенные границы

- Не менять `/opt/mo54`, `mo54.service` и существующие контейнеры MO54.
- MO54 Calls развёрнут отдельно в `/opt/asterisk-crm` и доступен через `calls.мягкиеокна54.рф`.
- Внешний nginx обслуживает HTTPS; API приложения не публикуется напрямую, а слушает loopback/внутреннюю Docker-сеть.
- DNS-запись `calls` в Cloudflare должна оставаться **DNS only** (серое облако), пока не будет отдельно спроектирована совместимость прокси с webhook и API.

## Предварительная проверка на VPS

Выполнять от пользователя с доступом к Docker:

```bash
cd /opt/asterisk-crm
docker compose -p asterisk-crm ps
docker compose -p asterisk-crm logs --tail=100 api
docker compose -p asterisk-crm logs --tail=100 worker
curl --fail --silent --show-error https://calls.мягкиеокна54.рф/health
df -h /
```

Ожидается успешный health-check и работающие сервисы API, worker и PostgreSQL. Любое изменение конфигурации следует предварять копией текущего файла окружения **вне репозитория**.

## Обычное обновление

1. Убедиться, что локальная исходная версия проверена и помечена Git-тегом.
2. Передать на VPS только исходный код без `.env`, `private`, аудио, очередей и резервных копий.
3. На VPS обновить секреты отдельно от Git, включая ключ Novofon и секрет webhook.
4. Собрать и поднять только сервисы MO54 Calls:

```bash
cd /opt/asterisk-crm
docker compose -p asterisk-crm up -d --build api worker
```

5. Выполнить миграции штатной командой проекта, если новая версия их содержит.
6. Проверить логи и health-check, затем сделать один тестовый входящий звонок.

Не применять широкие команды очистки Docker и не перезапускать сервисы MO54. Перед любым изменением firewall сохранить текущие правила и отдельно проверить доступность MO54.

## Откат к предыдущей версии

1. Зафиксировать ошибку: время, логи API/worker, идентификатор сессии звонка Novofon.
2. На VPS перейти на предыдущий известный Git-тег/коммит исходного кода.
3. Вернуть совместимый с ним файл окружения из защищённой серверной копии.
4. Пересобрать только `api` и `worker`, затем выполнить health-check.

Миграции базы должны быть обратимыми или иметь отдельный план восстановления. Откат кода без оценки схемы БД может усугубить проблему.

## Диагностика интеграции

```bash
cd /opt/asterisk-crm
docker compose -p asterisk-crm logs --since=30m api | grep -i novofon
docker compose -p asterisk-crm logs --since=30m worker | grep -i novofon
```

В личном кабинете Novofon параллельно проверять журнал HTTP-уведомлений и детализацию звонка. Для расследования хранить идентификатор сессии, время и HTTP-статус, но не публиковать ключи и полный payload в открытых системах.
