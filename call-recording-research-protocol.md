# MO54 Calls: протокол исследования записи звонков на Android

Статус: `обязательный протокол spike`  
Дата: `2026-06-23`

## 1. Назначение

Автоматическая запись телефонных звонков на Android нестабильна как продуктовая гарантия: результат зависит от модели телефона, версии Android, прошивки, региона и системных ограничений.

Этот протокол нужен, чтобы разработчик не строил решение на предположениях. До финальной реализации он должен проверить телефон Игоря и зафиксировать, что реально работает.

## 2. Результат исследования

Разработчик должен передать:

- заполненный отчет по этому протоколу;
- APK или тестовый build, которым выполнялась проверка;
- тестовые аудиофайлы;
- скриншоты разрешений;
- список использованных API/подходов;
- вывод: `можно принимать`, `частично можно`, `нельзя принимать`, `нужна замена устройства`.

## 5. Тест входящего звонка

### 5.1. Подготовка

- Установить APK.
- Привязать устройство к backend.
- Выдать разрешения.
- Включить запись, если приложение поддерживает режим включения.
- Подготовить второй телефон для звонка.

### 5.2. Шаги

1. Позвонить на телефон Игоря со второго телефона.
2. Принять звонок.
3. Произнести тестовую фразу со стороны клиента:

```text
Тест входящего звонка, сторона клиента.
```

6. Проверить, появилась ли форма итога.

## 10. Решение по аудио

Каждый основной тест выполняется три раза подряд. Для допуска v1 все три
входящих и все три исходящих файла должны содержать разборчивую речь обеих
сторон. Автофраза не является блокирующим критерием.

Разработчик выбирает одно заключение:

| Заключение | Когда использовать |
|---|---|
| `можно принимать` | Входящие и исходящие звонки пишутся, обе стороны слышны, данные синхронизируются |
| `частично можно` | Фиксация звонков работает, но обе стороны записываются нестабильно; для v1 это go/no-go `no-go` |
| `нельзя принимать` | Нет надежной фиксации звонков или данные теряются |
| `нужна замена устройства` | Ограничения конкретного телефона не позволяют выполнить целевой сценарий |
